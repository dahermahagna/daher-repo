Signals Ping-Pong
 Keywords

signal
כשדיברנו על פרוססים אמרנו שמערכת ההפעלה נותנת לכל פרוסס משאבים משלו וכל פרוסס פועל בנפרד, אבל, מערכת ההפעלה מספקת לפרוססים דרכי תקשורת אחד עם השני.
אז סיגנלים זה בעצם סוג של מנגנון תקשורת בין פרוססים בלינוקס (inter-process communication (IPC.
סיגנל זה סוג של נוטיפיקציה אסינכרונית (אולי יש גם סינכרוני) שנשלחת לפרוסס או לthread מסויים בתוך פרוסס כדי להודיע לו שהתרחש אירוע כלשהו.

כאשר נשלח signal כלשהו לפרוסס, מערכת ההפעלה עוצרת את הפעילות של הפרוסס על מנת להעביר לו את הסיגנל. 
בפרוסס יכול להיות מוגדר signal hendler עבור כל סוג של סיגנל ואם הוגדר אז הוא יתבצע בעת קבלת הסיגנל, ובמידה ולא הוגדר תתבצע הפעולה הדיפולטיבית שמוגדרת לסיגנל. (נקרא גם default handler) 

המנגנון של סיגנלים מזכיר לכאורה את המנגנון של interrupts, אבל, בשונה מ-interrupt המגיע דרך המעבד ומטופל ע"י ה- kernel, סיגנלים נשלחים דרך ה-kernel  (כנראה באמצעות syscall) ומטופלים ע"י הפרוסס.  

בסטנדרט של C לכל סיגנל יש מספר integer ושם, למשל הסיגנל של abort נקרא SIGABRT והמספר שלו הוא 6 וכו', בעצם בספריה signal.h יש כנראה מאקרו לכל סיגנל שקיים בסטנדרט אז אפשר להשתמש בשמות של הסיגנלים ולא במספרים שלהם.
דוגמאות נוספות לסיגנלים סטנדרטיים והפעולות הדיפולטיביות לכל אחד תמצאו פה.
לפי גיקספורגיקס, עבור כל פרוסס, מערכת ההפעלה מנהלת את הסיגנלים באמצעות 2 אינטג'רים
Pending Signals Integer
Blocked Signals Integer
כל אחד מהם הוא int אז יש לו 32 ביטים וכל ביט מקושר לסיגנל, כלומר, אפשר לייצג עד 32 סיגנלים שונים.

כאשר סיגנל נשלח לתהליך הוא "מדליק" את הביט שמייצג אותו ב-Pending Signals Integer של התהליך. 
אם הביט של סיגנל "דלוק" בBlocked Signals Integer אז מתעלמים מהסיגנל ואין צורך לטפל בו.
כל פעם שמגיע תורו של פרוסס לקבל תשומת לב מהמעבד בודקים ב-Pending Signals Integer האם יש סינגל שממתין לטיפול והאם צריך לטפל בו לפי ה-Blocked Signals Integer. 
אם אין סיגנל בהמתנה או שיש אבל הוא blocked אז התהליך ממשיך לרוץ, אם יש סיגנל שממתין צריך לטפל בו אז מערכת ההפעלה מבצעת את ה-signal handler.

פעולות שיכולות להיות בסיגנלים:
Terminate - סיום חריג של התהליך. התהליך מסתיים עם כל ההשלכות של ()exit_, אבל האקזיט סטטוס זמין ל()wait ולwaitpid  מצביע על סיום חריג על ידי האות שצוין.
(Terminate (core dump - סיום חריג של התהליך. בנוסף, יכולות להתבצע פעולות סיום שהן  implementation-defined כמו יצירה של קובץ core
Ignore - התעלמות מהסיגנל.
Stop – עצור (לא סיים) את התהליך.
Continue – אם התהליך עצר אז המשך בתהליך, אחרת אם הוא לא היה בעצירה בכלל אז פשוט מתעלמים מהסיגנל

sigaction
 #include <signal.h>
int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);
sigaction היא system call והיא חלק מהAPI של POSIX והיא מאפשרת להגדיר את ההתנהגות של התוכנית כאשר מתקבל סיגנל, כלומר, היא מאפשרת להגדיר signal handler עבור סיגנלים שהםnon-system-reserved.
בעצם sigaction כשמה signal action מאפשרת לשנות את הaction שמתבצעת כאשר מתקבל סיגנל.
יש סיגנלים מסויימים שלא ניתן להגדיר עבורם התנהגות אחרת מהדיפולטיבית כמו SIGKILL, SIGSTOP.

הפרמטרים שהיא מקבלת:
signum - שם הסיגנל, יכול להיות כל סיגנל חוץ מSIGSTOP / SIGKILL (זה בעצם כנראה מקארו שמוגדר בספריה signal.h)
act - סטראקט מסוג sigaction שמוגדר בספריה signal.h שמכיל את ההנדלר החדש. זה המבנה שלו:
struct sigaction 
{ 
       void  (*sa_handler)(int);                 
       void  (*sa_sigaction)(int, siginfo_t *, void *);    /*alternative pointer to the function - 
   only one of them can be used*/
       sigset_t   sa_mask;
       int  sa_flags;
};
השדות האלה הכרחיים לstruct, אך ניתן להוסיף שדות נוספים.
sa_handler - זהו השדה הכי חשוב יכול לקבל אחד משלושה ערכים:
SIG_DF שיש להשתמש באופציית דיפולט של הסיגנל.
SIG_IGN - שאומר שצריך להתעלם מהסיגנל הזה.
פוינטר לפונקציה של ה-signal hendler.
sa_mask - מציין סיגנלים נוספים שיש לחסום (to be blocked) בזמן הריצה של ה-signal handler
          צריך להיות מאותחל עם (sigemptyset(3.
sa_flags - מציין דגלים נוספים - הדגלים השונים מפורטים במניואל
sa_sigaction - פוינטר אלטרנטיבי ל-signal handler. אפשר להשתמש או בזה או בsa_handler, אי אפשר בשניהם. אם רוצה להשתמש באופציה הזו, הדגל SA_SIGINFO צריך להיות מורם.

oldact - פוינטר שבמידה והוא לא NULL הפונקציה תשמור בתוכו את הפוינטר לפונקציה הקודמת שהייתה מוגדרת לסיגנל הזה, כלומר, את ההנדלר הישן.

הפונקציה sigaction מספקת מחליפה ראויה ואמינה לsignal הידועה לשמצה. 
הבעייתיות של פונקצית signal היא שה-signal handlers שהותקנו על ידי פונקציית signal יוסרו מיד לפני ביצוע ה-handlers. לכן יש להתקין מחדש הנדלים קבועים על ידי קריאה ל-signal מתוך ה-handler, דבר שגורם לחוסר אמינות במידה ומתקבל אות מאותו סוג במהלך ביצוע ה-handler אך לפני ההתקנה מחדש.
הבעיה הזו לא קיימת כאשר משתמשים בsigaction - הנדלרים שמותקנים על ידי הפונקציה sigaction ניתנים להתקנה קבועה, וניתן להגדיר signals שרוצים לחסום במהלך הריצה של ההנדלר. ה-signals שנחסמו ישוחררו מיידית אחרי הסיום של ההנדלר, כלומר, הם יהיו חסומים רק בזמן ההרצה של ההנדלר הזה.

signal default disposition
לכל signal יש default disposition נקרא גם default handler, זוהי למעשה התנהגות ברירת המחדל שמתבצעת ב-process כאשר מתקבל אליו סיגנל, אלא אם צוינה התנהגות אחרת ב-Signal Handling.
ב-multithreaded application הdisposition של כל הthread-ים זהה.
פרוסס בן שנוצר על ידי fork יורש עותק של ה-dispositions  שלו, כשאנו משתמשים ב-exec הדיספוזיציות של הסיגנל הנדלרים עוברות RESET להגדרות הדיפולטיביות של הסיגנלים. 
מה שהוא כן יורש מהאבא באופן תקין זה הגדרות של סיגנלים שצריך להתעלם מהם. 

ניתן לשנות את הdisposition של סיגנל ע"י הפונקציה sigaction (או signal אבל לא מומלצת).

signal mask
לכל תהליך קיים signal mask, זה משתנה מטיפוס sigset_t שמוגדר בספריה signals.h והוא מכיל את כל הסיגנלים שחסומים לאותו תהליך.
לכל תהליך יש signal mask משלו. כאשר נוצר תהליך חדש באמצעות fork, הוא יורש באופן אוטומטי את ה-signal mask מההורה שלו (זה נשמר גם לאחר השימוש ב- execv). 



אם תהליך מקבל סיגנל שמסומן כחסום, הסיגנל יושעה עד שהתהליך יסתיים או עד שתוסר החסימה של האות מה-mask.
פונקציית sigpending() תחזיר לנו את רשימת האותות החסומים לתהליך מסוים.

ניתן לשנות את הסיגנלים החסומים או לבטל חסימה ע"י הפונקציה sigprocmask.
בתהליכים שהם multi-threaded לכל thread יש signal mask משלו ואין signal mask של הפרוסס. במקרה זה השימוש בפונקציה sigprocmask הוא unspecified וצריך להשתמש בפונקציה pthread_sigmask.

System Calls
kill
#include <sys/types.h>
#include <signal.h>
int kill(pid_t pid, int sig);
פקודה המשמשת לשליחת סיגנל לפרוסס או לקבוצת פרוססים.
בהצלחה חוזר 0, בכשלון חוזר 1- וerrno מתעדכן. יכול להכשל למשל אם לפרוסס אין הרשאה לשלוח סיגנלים לפרוססים האלה.
 pid -
אם pid חיובי הסיגנל יישלח לפרוסס שיש לו את הpid הזה
אם pid == 0 הסיגנל יישלח לכל הפרוססים שבקבוצת פרוססים של הפרוסס הקורא
אם  pid == -1 הסיגנל יישלח לכל הפרוססים שהסיגנל השולח יש הרשאה לשלוח להם (פרט לפרוסס init)
אם pid < -1 הסיגנל ישלח לכל הפרוססים שבקבוצת הפרוססים שהpgid שלה שווה לpid-

sig - 
יכול להיות כל אחד מהסיגנלים שמוגדרים בsignal.h
אם 0 לא יישלח סיגנל אבל כן תתבצע בדיקה שהpid או pgid קיימים או שיש הרשאות לשלוח לpid הזה סיגנלים, זה יכול להיות שימושי.

raise
#include <signal.h>
int raise(int sig);
הפונקציה שולחת סיגנל לפרוסס/thread שקרא לה. 
בתוכנית שהיא single - threaded זה שווה ערך לשימוש בפונקציה:
kill(getpid(), sig);
בתוכנית שהיא multi - threaded זה שווה ערך לשימוש בפונקציה:
pthread_kill(pthread_self(), sig);
אם הסיגנל שנשלח ע"י raise מוביל לקריאה להנדלר, הפונקציה תחזור רק לאחר שההנדלר יחזור. 
מחזירה 0 בהצלחה ו- non-zero בכישלון. 


pause
#include <unistd.h>
int pause(void);
הפונקציה גורמת לפרוסס/thread שקרא לה לישון/להשהות את הפעולה שלו עד שמתקבל סיגנל שמפעיל הנדלר או שtermintes את הפרוסס.
אם ההתקבל סיגנל שגרם להפעלת הנדלר אז pause תחזור אחרי שהיא תפעיל את ההנדלר וזה נחשב כשלון כי "הצלחה" של הפונקציה נחשבת השהיית הפרוסס לנצח והערך חזרה יהיה  1- וerrno מתעדכן.
אם התקבל סיגנל גורם ל-termination הפונקציה pause לא תחזור ולא יהיה ערך חזרה.

***פונקציה זו מהווה נקודת ביטול בתוכניות multi - threaded. זו בעיה אם thread מקצה שאבים (כמו זיכרון, file descriptors, semaphores or whatever) בזמן הקריאה לpause. אם thread יתבטל, משאבים אלה יישארו מוקצים עד לסיום התוכנית. כדי להימנע מקריאות לפונקצית pause יש להגן באמצעות cancellation handlers.

#include <signal.h>
int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);
פקודה המשמשת לשינוי/לאחזור ה-signal mask של תהליכון. לפקודה 3 סוגי חתימות, עבור sys call של לינוקס נשתמש בזו המופיעה כאן.
הארגומנטים:
how - מאקרו שמייצג את אופן השינוי:
    SIG_BLOCK - הוספת האותות שב-set ל-signal mask.
    SIG_UNBLOCK - הסרת האותות שב-set מה-signal mask.
SIG_SETMASK - דורס את מה שמוגדר בsignal mask ושם את מה שיש ב-set.
set - מצביע לאובייקט מסוג sigset_t שמגדיר את האותות שברצוננו לשנות ב-signal mask. במידה ונשלח set שהוא NULL, הפונקציה תתעלם ממנו.
oldset - מצביע לאובייקט מסוג sigset_t שהפונקציה מגדירה כדי לציין את ה-signal mask הנוכחי, במצב הקיים. כלומר אחרי ביצוע הפונקציה זה יהיה המצב הישן.
הפונקציה תחזיר 0 במצב של הצלחה ומינוס 1 במצב של כישלון + תעדכן errno.

בתהליכים שהם multi-threaded לכל thread יש signal mask משלו ואין signal mask של הפרוסס. במקרה זה השימוש בפונקציה sigprocmask הוא unspecified וצריך להשתמש בפונקציה pthread_sigmask.

signalfd
#include <sys/signalfd.h>
int signalfd(int fd, const sigset_t *mask, int flags);
הפונקציה משמשת ליצירת file descriptor שיכול לשמש לקבלת סיגנלים לפרוסס שקרא לפונקציה.
זה יכול להיות תחליף ל-signal handler או ל-sigwaitinfo ויש לזה ייתרון כי אפשר לבקר על ה-file descriptor  באמצעות ()select(), poll(), epoll.

הפונקציה מחזירה file descriptor


fd - 
חייב להיות signalfd file descriptor 
אם 1- הפונקציה תיצור file descriptor חדש

mask - הסיגנלים שהפרוסס שקרא לפונקציה רוצה לאפשר לקבל אותם באמצעות הfile descriptor. אי אפשר לקבל את הסיגנלים SIGKILL, SIGSTOP באמצעות הfile descriptor, ויתעלמו מהם גם אם הם יופיעו בmask.  ידרוס את הmask הקיים שכבר משוייך לקובץ.

flags - דגלים שמשפיעים על התנהגות של הfile descriptor
SFD_NONBLOCK
SFD_CLOEXEC

הפונקציות הבאות משתמשות לערוך משתנה מסוג sigset_t שמשמש לקביעת סיגנלים חסומים/פתוחים:
sigemptyset
#include <signal.h>
int sigemptyset(sigset_t *set);
משמשת לרוקן את התוכן של משתנה מסוג sigset_t שמקבלת, כלומר, קובעת שכל הסיגנלים כבויים.
מחזירה 0 בהצלחה, 1- בכישלון ומעדכנת את errno.

sigfillset
#include <signal.h>
int sigfillset(sigset_t *set);
ממלאת את הset, כלומר קובעת שכל הסיגנלים דלוקים.
מחזירה 0 בהצלחה, 1- בכישלון ומעדכנת את errno.

sigaddset
#include <signal.h>
int sigaddset(sigset_t *set, int signum);
מוסיפה סיגנל מסויים לset, כלומר "מדליקה" סיגנל מסויים בסט.
מחזירה 0 בהצלחה, 1- בכישלון ומעדכנת את errno.

sigdelset
#include <signal.h>
int sigdelset(sigset_t *set, int signum);
מסירה סיגנל מסויים מהset, כלומר "מכבה" סיגנל מסויים בסט.
מחזירה 0 בהצלחה, 1- בכישלון ומעדכנת את errno.

מה ההבדל בין הפונקציות signal, sigaction?
ההבדלים:
הפונקציה signal לא בהכרח חוסמת signals אחרים בזמן שהיא מפעילה את ה-handler שלה,  בעוד ש-sigaction כן חוסמת.
לאחר שהפונקציה signal מריצה handler מסוים, היא מאפסת (reset) את הערך של הsignal action ל-SIG_DFL (דיפולט). זה אומר שבנוסף לפעולות הרגילות של ההנדלר, הוא חייב לדאוג להתקין את עצמו מחדש כפעולה הראשונה של הsignal הזה בכל פעם שהוא רץ. זה פתח לבלאגן כי יכול להיות זמן הפקר של התנהגויות בלתי מוגדרות.
לעומת זאת, sigaction לא עושה את כל זה.
ההתנהגות של פונקציית signal משתנה ממערכת למערכת וזה אומר שאני צריכה לדעת מה הארכיטרקטורה שלי כדי לדעת למה לצפות ממנה. כלומר היא לא פורטבילית הסתומה הזאת.
לעומת זאת, sigaction מוגדרת אותו דבר לכל המערכות.
זה undefined אם יש קריאה לsignal כשהפרוסס שלי הוא multi threaded.
